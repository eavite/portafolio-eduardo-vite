The problem I wanted to solve

At closing, I needed to compare two versions of the same payments: the system records and the bank report. A repeated reference, a different amount or a closing cutoff could make the review harder.

The solution

The tool reads the files, matches payments and separates the differences. The result shows what matches, what is missing from each report and what needs another look.

What it adds to closing

Differences are separated from matching payments. The output keeps the detail needed to investigate each case and return to the source file. A pending item is never automatically deleted or considered resolved.

Lessons from the project

A reference alone may not identify a payment. Combining it with the customer prevents incorrect matches. Payments recorded after the cutoff are kept separate so they are not mistaken for missing transactions.

Purpose and tools

The program was created to support the daily collections close: compare system records with bank receipts and make the payments that need review easy to find.

It aims to reduce manual row-by-row comparisons and bring the differences together in one result. Each payment keeps its customer, reference and amount, giving the review a clear starting point and a way back to the source file.

For data analysis, it provides an organized set of records to filter pending cases, check totals and distinguish payments recorded outside the closing period. The information is then ready for investigating differences and preparing further reports.

  • Python: organizes the processing steps and generates the output files.
  • pandas: reads reports, organizes records and compares payments.
  • SQL with SQLite: looks up sample services related to pending payments.
  • Tkinter: provides a desktop window for using the program.

This demonstration uses fictional data. Results are saved as CSV files that can be reviewed in Excel; pending payments still require review.
